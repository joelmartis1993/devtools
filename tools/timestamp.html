What is a Unix timestamp?

A Unix timestamp (also called epoch time) is the number of seconds elapsed since 00:00:00 UTC on 1 January 1970, ignoring leap seconds. It's the canonical way computers store and exchange points in time — you'll find it in databases, server logs, JWT iat/exp claims, HTTP cookies, and almost every API. Knowing how to convert Unix timestamp to readable date in JavaScript, Python, or any other language is a daily task for backend developers.

Tips & best practices

  • If your number has 10 digits it's almost certainly seconds; 13 digits is milliseconds. The auto-detect threshold here is ≥ 1e12.
  • Always serialize timestamps in UTC (ISO 8601 with a trailing Z) for storage and transport — convert to local time only at the UI layer.
  • Beware the year 2038 problem: 32-bit signed seconds overflow on 19 January 2038. Use 64-bit integers for any new system.

Frequently asked questions

How to convert Unix timestamp to readable date in JavaScript?

Use new Date(timestamp * 1000).toISOString() if your value is in seconds, or new Date(timestamp).toISOString() if it's already in milliseconds. This tool does both automatically.

Why does the timestamp look different in my database?

Most SQL databases store timestamps as ISO date strings or in milliseconds. PostgreSQL's extract(epoch from now()) returns seconds with a fractional part; truncate or round depending on what your app expects.

What is a relative timestamp?

A human-friendly description like "2 hours ago" or "in 3 days". This page derives it from the parsed timestamp and the current clock.

Does this support timezones?

Yes. Pick any IANA timezone in the dropdown to see how the same instant looks in that location. Storage is always UTC; the timezone only affects display.
