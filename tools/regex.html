What is a regex tester?

A regex tester with examples for developers shortens the feedback loop between writing a pattern and seeing what it matches. Regular expressions are powerful but notoriously hard to read; a live tool that highlights matches in color and breaks out capture groups separately turns "guess and check" into a deliberate process. DevToolsHive uses the JavaScript regex engine — the same one that runs in browsers and Node.js — so anything that works here works in your code.

How to use it

  1. Type or paste your pattern in the top input. Don't include the surrounding slashes.
  2. Toggle the flags you need (or type them directly).
  3. Paste the text to test against. Matches highlight as you type.
  4. Read the capture groups in the match list — each numbered group is shown separately.
  5. Pick a preset from the chip row to load a battle-tested pattern (email, URL, phone, password).

Real-world examples

Extract every email from a log file

Pattern [\w.+-]+@[\w-]+\.[\w.-]+ with the g flag. Paste 200 KB of log lines and copy out every address with one click.

Validate a hex color

^#(?:[0-9a-fA-F]{3}){1,2}$ — passes #fff and #1a2b3c, rejects #zzz or anything with extra characters.

Strong password check

^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[^\w]).{8,}$ — at least 8 characters, mixed case, a digit, and a symbol.

Common use cases

  • Validating form input (emails, phone numbers, postal codes)
  • Extracting structured data from unstructured text or logs
  • URL routing and rewriting
  • Search-and-replace operations across a codebase
  • Tokenizing input for parsers and lexers

Tips & best practices

  • Anchor with ^ and $ when you mean "the whole string", not just "any match within".
  • Prefer non-capturing groups (?:…) when you don't need to extract — they're slightly faster and keep .match() output clean.
  • Beware of catastrophic backtracking with patterns like (a+)+ on long inputs.
  • For Unicode text, always use the u flag — without it, \w only matches ASCII.
  • Test with malicious or empty input, not just the happy path.

Frequently asked questions

What is regex used for?

Regular expressions describe patterns in text. Developers use them to validate input, extract data from logs, perform search-and-replace, and parse simple grammars.

How do I match newlines with a dot?

By default, . does not match \n. Add the s (dotall) flag, or use [\s\S] as a portable alternative.

Why does my pattern only match the first occurrence?

You're missing the g (global) flag. Without it, the engine stops after the first match.

What's the difference between \d and [0-9]?

Without the u flag they're equivalent. With u, \d still only matches ASCII digits — [0-9] is the safer literal.
