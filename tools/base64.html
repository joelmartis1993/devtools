About Base64 encoding

Base64 is a binary-to-text encoding that represents arbitrary bytes using 64 printable ASCII characters. It's used everywhere in modern web development: embedding small images in CSS as data: URIs, storing binary fields in JSON, signing JWT tokens, and transmitting credentials in HTTP Authorization headers.

Encode vs decode

Use encode to turn human-readable text or binary data into a transport-safe ASCII string. Use decode to reverse the operation. The optional URL-safe mode replaces the characters + and / with - and _ and removes padding — the variant required by JWT, OAuth, and most URL-embedded tokens.

Practical examples

  • Decoding a JWT payload to inspect its claims (paste the middle segment).
  • Building a Basic Auth header: encode username:password and prefix with Basic .
  • Inspecting data:image/png;base64,… blobs from CSS or HTML.
  • Sending UTF-8 strings through systems that mangle non-ASCII bytes.

UTF-8 handling

Unlike many naive Base64 tools, this encoder correctly handles multi-byte UTF-8 characters — emoji, accented Latin, Cyrillic, CJK, and so on — by encoding the byte representation rather than the code points. Decoding will round-trip these characters losslessly.

Need to encode for a query string instead? Use the URL encoder.

Frequently asked questions

What is Base64 encoding used for?

Base64 makes binary data safe to transport through text-only channels: HTTP headers, URLs, JSON payloads, JWTs, email attachments, and inline images in CSS or HTML.

Why do I get "InvalidCharacterError" when decoding?

The input contains characters outside the Base64 alphabet, or has the wrong padding. If your token uses - and _, enable URL-safe mode.

Does Base64 encrypt my data?

No. Base64 is encoding, not encryption. Anyone can decode it. Use it for transport safety only — never as a security measure.

How do I decode a JWT with Base64?

A JWT has three dot-separated parts. Copy the middle (payload) segment and decode it with URL-safe mode on. The result is JSON you can pretty-print in the JSON formatter.

Does this support UTF-8 characters like emoji?

Yes. The encoder converts strings to UTF-8 bytes first, so emoji and CJK characters round-trip losslessly.
